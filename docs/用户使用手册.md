## 📱 一、系统概述

### 1.1 系统定位

广企通一户一表 CRM 移动端是一款面向银行对公业务的客户关系管理系统，支持：
- **客户经理**：待办管理、客户跟进、拜访录入
- **分行/中支**：机构督导、清单下发、进度跟踪
- **总行**：经营看板、全行督导、需求池管理

### 1.2 核心特性

✅ **自动化数据回流**：ECIF、核心系统、薪福宝等业务系统数据自动同步  
✅ **智能待办分类**：待触达、预警、路演、模块提升四类事项自动归集  
✅ **铁三角协同**：对公、零售、科技三方联动路演记录  
✅ **需求池归集**：客户功能诉求自动汇总至总行产品优化池  
✅ **清单全流程**：总行下发 → 分行接收 → 客户经理跟进，全程可追溯

#### 3.1.4 拜访跟进录入

**位置：** 客户详情 → 录入本次拜访

**表单结构：**

| 字段 | 类型 | 说明 |
|------|------|------|

| 企业规模 | 单选 | 50人以下/50-200人/200-500人/500人以上 |
| 业务意向 | 多选 | 代发、薪福宝、企业网银、银企直连、授信咨询 |
| 客户反馈 | 多选 | 考虑中、意向明确、需进一步演示、价格敏感… |
| 已推介产品 | 多选 | 薪福宝、代发、企业网银… |
| 下次跟进动作 | 单选 | 安排路演、产品演示、意向确认、例行回访 |
| 下次跟进日期 | 日期 | - |
| 补充说明 | 文本域 | 选填 |
| **客户需求（功能诉求）** | **复合** | **⭐ 重点：同步需求池** |

**功能诉求模块（重点）：**
```
☑ 客户需求（功能诉求） · 选填
  勾选后可填写，涉及系统功能提升的诉求将自动归集至需求池
  
  涉及产品/系统：[薪福宝] [企业网银] [代发系统] [一户一表/CRM]
  
  功能诉求类型：
  [流程审批优化] [假期考勤联动] [移动端体验] [OA/HR系统对接]
  [批量操作简化] [报表导出增强] [消息通知增强] [界面易用性]
  
  诉求描述：（文本框）
  记录客户原话或具体使用场景，如「审批层级太多，希望按天数自动路由」…
```

**自动生成摘要：**
- 根据表单勾选项自动组合生成业务摘要
- 示例：`首次拜访，企业规模 50-200人；业务意向：代发、薪福宝；客户考虑中；已推介薪福宝；下次安排路演。功能诉求【薪福宝·流程审批优化】：审批层级太多。（已同步需求池）`

## 🔄 四、数据回流机制

### 4.1 回流数据源

| 数据源 | 回流内容 | 更新频率 | 展示位置 |
|--------|----------|----------|----------|
| **ECIF** | 签约产品、企业网银登录、银信通状态、理财余额 | T+1（每日08:30） | 一户一表 · 产品使用情况 |
| **核心系统** | 代发笔数、代发金额、账户交易 | 实时/T+1 | 一户一表 · 产品使用情况 |
| **薪福宝** | 模块开通情况、登录次数、使用深度 | 实时 | 一户一表 · 薪福宝模块 |
| **开户系统** | 新开户识别、自动注入清单 | T+1 | 清单 · 增量注入 |
| **流水跑批** | 授信机会识别 | 每日批量 | 总行看板 · 授信池 |

### 4.2 回流展示规则

1. **针对性回流**：仅展示**本客户已签约**的产品数据
   - 未签约产品显示「未签约」，不占用视觉空间
   
2. **数据溯源标签**：每条数据标注来源系统 + 更新时间
   - 示例：`[核心 · 06-24]` `[ECIF · 06-26]` `[薪福宝 · 实时]`

3. **预警标注**：异常数据红色高亮
   - 示例：`网银 30 天未登录`（红色）、`代发笔数骤降`

4. **空态提示**：
   - 未签约客户：「客户尚未签约行内产品，暂无使用回流数据」
   - 已签约待激活：「已签约薪福宝+代发，薪福宝待开通，代发签约后尚未发生」

### 4.3 回流流程图

## 📖 七、常见问题

### Q1：为什么有的客户没有产品使用数据？

**A：** 一户一表采用「针对性回流」机制，**仅展示本客户已签约的产品数据**。
- 未签约客户：显示「尚未签约行内产品，暂无使用回流数据」
- 已签约待激活：显示产品名但数据为空（如「代发签约后尚未发生」）

### Q2：数据更新频率是多少？

**A：** 不同系统更新频率不同：
- 薪福宝：实时
- 核心系统（代发）：实时/T+1
- ECIF（网银登录、理财）：T+1（每日 08:30）
- 流水跑批（授信）：每日批量

每条数据都带溯源标签，如 `[核心 · 06-24]` 表示来自核心系统，6月24日更新。

### Q3：功能诉求如何同步到需求池？

**A：** 客户经理在「拜访跟进录入」表单中：
1. 勾选「客户需求（功能诉求）」
2. 填写涉及产品/系统、功能诉求类型、诉求描述
3. 保存时自动归集至需求池
4. 总行产品团队在「需求池 Tab」查阅并推动优化

### Q4：清单是如何流转的？

**A：** 清单全流程：
```
总行下发 → 分行接收 → 分配至客户经理 → 触达跟进 → 转化/复盘
```
- 园区批量：总行手动下发
- 增量注入：开户系统识别后 T+1 自动注入
- 存量清单：ECIF 定期推送

### Q5：如何调整管户人？

**A：** 三种场景：
- **同网点调整**：客户经理自行协调，系统不干预
- **跨网点调整**：分行/中支在清单管理中发起改派
- **跨分行攻坚**：总行在清单管理中发起改派

系统保留调整留痕，被改派人收到通知。
